# Каталог профилей

Учебный сервер рядом с тестовой визиткой. Визитка отвечает на вопрос «кто этот один человек». Каталог отвечает на вопросы «какие есть люди», «кто умеет TypeScript», «кто работал в компании с этим ИНН», «кто занимал эту должность» и «дай навык, опыт, компанию или должность отдельным списком».

Один процесс Nest на Express. Одни сервисы и репозитории. Два входа: REST-контроллеры и GraphQL-резолверы. Новый модуль появляется только вместе с новым сценарием.

## Данные

Профилей много. `ownerKey` уникален и является адресом человека в обоих API.

Навык — справочник. `Skill.name` уникален. Карточка держит связь `ProfileSkill` (`profileId`, `skillId`, `sortOrder`): порядок свой у человека, название общее. Две карточки с одним названием ссылаются на одну строку навыка.

Компания — справочник. `Company.inn` уникален и является адресом компании в обоих API. Название компании ключом не является: похожие названия остаются разными строками, пока ИНН разный. Один ИНН — одна строка.

Должность — справочник. `Position.name` уникален. Одна и та же должность у разных людей — одна строка.

Опыт принадлежит одному профилю и ссылается на справочники: `profileId`, `companyId`, `positionId`, дата начала, дата окончания. Названия компании и должности в опыте текстом не хранятся. Пустая дата окончания значит, что работа продолжается.

Проект и ссылка принадлежат одному профилю. Общего справочника у проекта и ссылки нет.

Пустая связь — пустой список.

## Запись

Пишет только seed. Через API карточки не создаются.

Опыт выбирает компанию из справочника по ИНН. Если компании с этим ИНН нет, её сначала создают отдельной строкой справочника — ИНН и название — и только потом выбирают в опыте. Строка опыта компанию не создаёт и название компании не хранит.

Должность опыт выбирает из справочника по названию. Навык на карточке выбирают из справочника по названию.

Повторный запуск оставляет те же справочники: компания поднимается по ИНН, должность и навык — по названию, профиль — по `ownerKey`. Повторное создание той же компании не добавляет вторую строку.

## Модули

| Модуль | Сценарий | База |
| --- | --- | --- |
| `profile` | карточка, список карточек, фильтр по навыку, отдельные списки опыта, проектов и ссылок | свой репозиторий: скаляры профиля и пакетные выборки его связей |
| `skills` | справочник, число людей на навык, люди с навыком | свой репозиторий: один запрос справочника или один запрос связи |
| `companies` | справочник, число опытов и число людей у компании, опыты этой компании | свой репозиторий: один запрос справочника или один запрос опытов компании |
| `positions` | справочник, число опытов и число людей у должности, опыты этой должности | свой репозиторий: один запрос справочника или один запрос опытов должности |

`profile` импортирует `skills`, чтобы по имени фильтра получить id навыка. Список профилей после этого читает репозиторий `profile`.

`profile` импортирует `companies` и `positions`, чтобы по id опыта пакетно подставить компанию и должность. Для этого вызываются методы «найти строки справочника по id». Методы аналитики справочника карточку не собирают.

Таблицу опыта читают три сценария, каждый своим запросом: `profile` — опыты человека, `companies` — опыты компании, `positions` — опыты должности. Аналитика не вызывает соседний модуль в цикле.

Проект и ссылка своих модулей не получают. Их отдельные списки — ещё один вход `profile`: те же строки, без сборки целой карточки.

Внутри модуля по-прежнему слои. Контроллер и резолвер не вызывают Prisma. Сервис не носит `@Get`, `@Query` и `@ResolveField` и не пишет условия запросов. Репозиторий не собирает HTTP- или GraphQL-ответ.

## Аналитика

Аналитика запрашивается у конкретной сущности, отдельным полем. Общего отчёта по каталогу нет.

У сущности два вида полей по каждой прямой связи из базы: число и список связанных строк. Число не читает эти строки. Список не считает соседние связи. Поле, которое клиент не выбрал, базу не трогает.

Дальше клиент идёт вглубь полями уже полученной сущности. Следующий шаг возможен только по связи, которая есть в базе. Глубина не зафиксирована числом уровней: каждый выбранный уровень — одно пакетное чтение по id родителей этого уровня.

Повторный заход по кругу (человек → опыт → компания → опыты компании → человек) снова выбирает поля. Сервер этот круг сам не разворачивает.

| Сущность | Прямые связи | Поля аналитики |
| --- | --- | --- |
| `Profile` | навыки, опыты, проекты, ссылки | `skillCount`, `experienceCount`, `projectCount`, `linkCount` и сами списки |
| `Skill` | профили через `ProfileSkill` | `profileCount`, `profiles` |
| `Company` | опыты | `experienceCount`, `profileCount` (разные люди), `experiences` |
| `Position` | опыты | `experienceCount`, `profileCount` (разные люди), `experiences` |
| `Experience` | профиль, компания, должность | сами связи, без отдельного числа: у опыта одна компания, одна должность и один владелец |
| `Project` | профиль | `profile` |
| `ProfileLink` | профиль | `profile` |

Поле `skills` внутри карточки — сценарий `profile`. Поле `profiles` внутри навыка — сценарий `skills`. Опыты внутри компании — сценарий `companies`. Опыты внутри должности — сценарий `positions`. Компания и должность внутри опыта — сценарий карточки: пакетная подстановка справочника, не пересчёт аналитики компании.

## GraphQL

Корень:

```graphql
type Query {
  profiles(skill: String): [Profile!]!
  profile(ownerKey: String!): Profile
  skills: [Skill!]!
  skill(name: String!): Skill
  companies: [Company!]!
  company(inn: String!): Company
  positions: [Position!]!
  position(name: String!): Position
  experiences: [Experience!]!
  projects: [Project!]!
  links: [ProfileLink!]!
}
```

Карточка вложена так же, как в тестовом задании: `skills`, `experience`, `projects`, ссылки. Эти поля читает `@ResolveField` через loader текущего запроса. Запрос только имени не читает связи и не считает их. Список из десяти карточек с навыками — два SQL: профили и одна выборка навыков по их id.

Навык, компания и должность:

```graphql
type Skill {
  name: String!
  profileCount: Int!
  profiles: [Profile!]!
}

type Company {
  inn: String!
  name: String!
  experienceCount: Int!
  profileCount: Int!
  experiences: [Experience!]!
}

type Position {
  name: String!
  experienceCount: Int!
  profileCount: Int!
  experiences: [Experience!]!
}
```

Опыт в карточке и в отдельном списке:

```graphql
type Experience {
  ownerKey: String!
  startedOn: String!
  endedOn: String
  profile: Profile!
  company: Company!
  position: Position!
}
```

`ownerKey`, `inn` и название должности — адреса, по которым строку опыта можно сопоставить со справочниками. Выбор `company { experienceCount experiences { profile { name } } }` — уже аналитика компании и следующий уровень, отдельными чтениями.

Проект и ссылка в отдельных списках содержат `ownerKey` и поле `profile`.

Пример обхода вглубь по связям базы:

```graphql
query {
  company(inn: "7700000000") {
    name
    profileCount
    experiences {
      position { name }
      profile {
        name
        skills { name }
      }
    }
  }
}
```

Здесь отдельные чтения: компания, число разных людей, опыты этой компании, должности этих опытов одним пакетом, профили этих опытов одним пакетом, навыки этих профилей одним пакетом.

## REST

Те же сценарии, другие входы. Маршрут отдаёт свою сущность и её прямую связь. Следующий уровень — другой маршрут. Вложенное дерево, которое GraphQL собирает выбором полей, один REST-ответ не собирает.

| Метод и путь | Сценарий |
| --- | --- |
| `GET /profiles` | список карточек, скаляры |
| `GET /profiles?skill=TypeScript` | тот же список, фильтр по id навыка |
| `GET /profiles?include=skills` | скаляры и одна пакетная выборка навыков |
| `GET /profiles/:ownerKey` | одна карточка |
| `GET /profiles/:ownerKey?include=skills,experience,projects,links` | карточка и только названные связи |
| `GET /skills` | справочник и число людей |
| `GET /skills/:name` | один навык и профили, у которых он есть |
| `GET /companies` | справочник, число опытов и число людей |
| `GET /companies/:inn` | одна компания и её опыты |
| `GET /positions` | справочник, число опытов и число людей |
| `GET /positions/:name` | одна должность и её опыты |
| `GET /experiences` | все записи опыта с адресами владельца, компании и должности |
| `GET /projects` | все проекты |
| `GET /links` | все ссылки |

Без `include` список и карточка не читают связи и не считают их. `include=experience` подставляет компанию и должность этих опытов пакетно, без `experienceCount` компании. Числа справочника отдают `GET /companies` и `GET /positions`.

Опыт внутри `GET /companies/:inn` и `GET /positions/:name` содержит адреса `ownerKey`, ИНН и название должности. Карточка человека с этого опыта читается отдельным `GET /profiles/:ownerKey`.

## Что сознательно не входит

Запись карточек через API, авторизация, отклики и вакансии. Пока их нет, у них нет модуля. Данные каталога, как и у визитки, заполняет seed.
